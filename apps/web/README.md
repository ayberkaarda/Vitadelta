# Vitadelta web

Angular single-page application for Vitadelta (standalone components, signals, zoneless change
detection, Transloco, plain SCSS). It is served by nginx on the same origin as the API
(`/api/v1`).

## Requirements

- Node.js 22.23 or newer
- npm (the committed `package-lock.json` files are authoritative)

## Commands

| Command                   | Purpose                                                                        |
| ------------------------- | ------------------------------------------------------------------------------ |
| `npm ci`                  | Install the locked dependencies                                                |
| `npm start`               | Development server on `http://localhost:4200`                                  |
| `npm run lint`            | ESLint, Prettier check, e2e type check and the i18n template check             |
| `npm run format`          | Apply Prettier formatting                                                      |
| `npm test`                | Unit tests with Vitest (jsdom, single run) and the 70 % line coverage gate     |
| `npm run build`           | Production build into `dist/web/browser` (no source maps), then the size check |
| `npm run bundle:check`    | Self-test, then fails when the initial files exceed 380 kB gzipped             |
| `npm run i18n:check`      | Fails when a template contains literal user-facing text outside i18n           |
| `npm run api:types`       | Regenerates `src/app/core/api/schema.d.ts` from the public contract            |
| `npm run api:check`       | Fails when `schema.d.ts` differs from a fresh generation                       |
| `npm run e2e`             | Playwright end-to-end suite against the running stack (see below)              |
| `npm run e2e:screenshots` | Writes the six README images to `docs/screenshots/` from the running stack     |
| `npm run e2e:install`     | Downloads the headless Chromium the suite runs in                              |

## Structure

```
src/app/
  app.config.ts, app.routes.ts   providers and top-level routes (one line per feature)
  core/
    api/        schema.d.ts (generated), api-types.ts, ApiClient, ApiProblem
    auth/       SessionStore, RefreshCoordinator, authInterceptor, guards, returnUrl, fragment token
    state/      QueryStore, CurrencyStore, RegionStore, UnreadCountStore
    format/     Formatter (Intl in the active locale)
    i18n/       languages, loader, featureRoutes(), title strategy
  shared/       presentational components (bars, badges, money, notices, form fields, drawer, …)
  shell/        ShellComponent (header, menu sheet, footer), not-found page
  features/     one folder per feature: <feature>.routes.ts plus its pages
  testing/      test helpers and synthetic fixtures (not part of the build)
public/i18n/    en.json, tr.json (shell and shared keys) and <feature>/{en,tr}.json scopes
tools/openapi/  isolated generator package (openapi-typescript needs TypeScript 5.x)
e2e/            Playwright end-to-end suite (flows, support helpers, synthetic import fixture)
```

## Notes

- Change detection is zoneless; `zone.js` is not a dependency.
- API types are generated by `openapi-typescript` in the isolated `tools/openapi` package (its
  own lock file, TypeScript 5.9). The first line of `schema.d.ts` records the SHA-256 of the
  contract; a unit test fails when the contract changes without regenerating the types.
- `ApiClient` is hand-written (no generated runtime): one typed method per contract operation,
  every error mapped to `ApiProblem`. The access token lives in memory only and is attached by
  the auth interceptor, which refreshes once on a `401` through the single-flight
  `RefreshCoordinator` (Web Locks plus `BroadcastChannel` across tabs).
- User-facing copy lives in `public/i18n`: the root files hold shell and shared keys, every
  feature has its own scope folder loaded lazily with its routes. A unit test checks that each
  language pair has identical keys, no empty strings and matching parameters.
- Entitlements are never computed in the client: quota chips, locked rows and limit notices
  render the server's counters, `meta.visibility` and `upgradeHint`.
- The production `index.html` contains no inline scripts or event handlers (critical CSS
  inlining is disabled), so the app runs under the strict Content Security Policy served by
  nginx. A unit test rejects HTML injection sinks and sanitizer bypasses anywhere in `src`.
- Design tokens (light and dark via `prefers-color-scheme`) are in `src/styles/_tokens.scss`;
  global layout, control and data classes are in the other `src/styles` partials.

## End-to-end tests

The suite in `e2e/` drives the built app through nginx with headless Chromium (Playwright,
`@axe-core/playwright` for the accessibility scan). It expects the Docker Compose stack to be
running and seeded, started with a bootstrap admin in the root `.env`:

```bash
bash scripts/dev-down.sh --volumes   # optional: start from an empty database
bash scripts/dev-up.sh --bootstrap-admin   # fills an empty bootstrap admin in the root .env
bash scripts/seed.sh
cd apps/web
npm run e2e:install                  # once per machine
npm run e2e
```

| Variable                                | Default                   | Purpose                                 |
| --------------------------------------- | ------------------------- | --------------------------------------- |
| `E2E_BASE_URL`                          | `http://localhost:8080`   | Public origin of the stack (nginx)      |
| `E2E_MAILPIT_URL`                       | `http://127.0.0.1:8025`   | Mailpit API for verification mails      |
| `E2E_ADMIN_EMAIL`, `E2E_ADMIN_PASSWORD` | values of the root `.env` | Bootstrap admin used by the admin flows |

- The global setup checks the stack and the seed, refreshes the exchange rates as admin and
  re-imports the seeded offers, so the price-drop flow always starts from the seeded prices.
- The flows run in one worker in file order: anonymous quota and locked rows, breakdown,
  keyboard-only run and 375 px smoke; compare GOLD-A vs GOLD-B, product, privacy, CSP headers;
  the account journey (register, Mailpit link, login, paged results, reload with silent
  refresh, USD display currency, save and price-drop alert, FREE limit, admin offers import
  and promo code in the UI, bell and inbox, promo redemption to PRO, language switch, logout);
  password reset and account deletion; the admin products JSON import.
- Every page is watched for console errors, uncaught exceptions and CSP violations; axe runs on
  each main page and fails on serious or critical WCAG 2.1 A/AA violations.
- The API rate limits are per client IP and in memory (for example 5 registrations per hour,
  30 anonymous queries per day), so repeated runs need a restarted API (`dev-down` + `dev-up`,
  or restarting the `api` service).
- Output (traces and screenshots of failures, HTML report) goes to `e2e/.output/`, which is not
  committed. `npx playwright show-report e2e/.output/report` opens the report.
- `RUN_E2E=1 bash scripts/test-all.sh` adds the suite to the full test run when the stack is up.
- `06-long-text.e2e.ts` answers every API call with mocked data whose product, brand, retailer,
  nutrient, notification, e-mail and file texts are long unbroken tokens, and checks at 375 and
  1280 px that no page scrolls sideways (wide tables may scroll inside their frame on phones).

### README screenshots

`npm run e2e:screenshots` (Playwright project `screenshots`, not part of `npm run e2e`) needs the
same running, seeded stack and global setup, and overwrites six images in `docs/screenshots/` at
the repository root: `overview-<lang>.png` (the query builder as a visitor),
`results-breakdown-<lang>.png` (signed-in results with the breakdown drawer open) and
`compare-<lang>.png` (GOLD-A vs GOLD-B with the verdict card and the per-nutrient table), for
`en` and `tr`. They use the synthetic TR fixtures only and a demo account
(`readme-demo@example.com`) that is registered and verified through Mailpit on the first run and
reused afterwards. Each image is 1280 px wide, light theme, scale 1; its height ends 16 px below
the last block shown, so no card, row or control is cut. The last test prints the six sizes.

```bash
cd apps/web
npm run e2e:screenshots
```
